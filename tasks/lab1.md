# Лабораторная работа №1. Базовая работа с git

## Цель работы

Познакомить студента с базовыми операциями при работе с git, дать необходимые
инструменты для работы в рамках курса.

## Процесс работы

По ходу выполнения работы фиксируйте промежуточные шаги для каждого этапа. Для
консольных команд в конце каждого этапа копируйте в отчет команды, которые
привели к успеху и их вывод, добавляя небольшое описание.

Для заданий, отмеченных ключевым словом *Узнайте*, выпишите в отчет краткий
конспект информации и укажите используемые источники.

## Этапы выполнения работы

### Установка и настройка

1. Установите программу `git`.
2. Убедитесь, что она доступна в командной строке с помощью команды
   `git --version`.
3. Укажите ваше имя и адрес электронной почты с помощью `git config`.
4. *Узнайте* основные команды git с помощью `git --help`.

### Начало работы с новым проектом

1. Создайте новую директорию для вашего проекта, создайте в ней новый
   репозиторий.
2. Создайте в этом репозитории файл `README.md`, директорию `reports` и файл
   `reports/lab1.md`.
3. *Узнайте* основные синтаксические элементы языка Markdown, который
   используется для содержимого файлов `.md`.
4. Напишите в файле `README.md` заголовок, информацию о дисциплине и о вас.
5. Создайте коммит с файлами `README.md` и `reports/lab1.md`.

### Отслеживание состояния кода

1. Выполните команду `git status` и `git diff`. Опишите, что они делают, и что
   означает их вывод.
2. Перенесите заметки по предыдущим этапам в файл `reports/lab1.md`.
3. Выполните команду `git status` и `git diff` снова. Объясните их вывод.
4. Добавьте изменения в файле отчета в индекс, но не создавайте коммит. Выполните
   `git status` и объясните вывод.
5. Внесите изменения в файл `README.md` (любые) и выведите на печать изменения
   только этого файла с помощью `git diff`.
6. Сделайте коммит с изменениями файла `reports/lab1.md`, но не `README.md`.

### Откат изменений

1. Убедитесь, что в файле `README.md` есть изменения, которые не были
   закоммичены.
2. Откатите эти изменения с помощью `git restore`. Убедитесь, что изменения
   пропали в файле.
3. Удалите файл `reports/lab1.md` (если переживаете, предварительно сделайте
   копию).
4. Выполните команду `git status` и объясните ее вывод.
5. Восстановите удаленный файл с помощью `git restore`.

### Ветвление версий

1. Выведите имя текущей ветку (`git branch`).
2. Создайте новую ветку с именем `lab1-1` и переключитесь на нее
   (`git checkout`).
3. Внесите в отчет протокол последних этапов в отчет и закоммитьте изменения.
4. Убедитесь, что эти изменения есть в файлах.
5. Переключитесь обратно на изначальную ветку. Проверьте содержимое файла
   отчета.
6. Внесите изменения в файл `README.md`, но не коммитьте их. Попробуйте
   переключиться на ветку `lab1-1`. Объясните результат.

### Слияние веток, конфликты

1. Откатите изменения в файле `README.md`.
2. Произведите слияние ваших ветвей командой `git merge` (ветвь `lab1-1` в
   основную).
3. Поменяйте в заголовок в файле `README.md` и закоммитьте изменения.
4. Переключитесь на ветку `lab1-1` и внесите следующие изменения:
  - добавьте новые части в отчет;
  - измените заголовок файла `README.md`, но не так, как в п. 3;
  - допишите что-то в конце файла `README.md`.
5. Закоммитьте изменения и попытайтесь слить ветку `lab1-1` с `main`. Объясните
   результаты.
6. Посмотрите на содержимое файла `README.md`. Разрешите конфликты и завершите
   слияние с помощью `git commit`.
7. Удалите ветку `lab1-1`.

### Работа с удаленным репозиторием

1. Создайте аккаунт на Github (если у вас его нет).
2. Добавьте себе или SSH ключ, или HTTP-токен. Сконфигурируйте их на своей
   машине. (Не вставляйте эти данные в отчет, их должны знать только вы!)
2. Создайте приватный репозиторий, ничего в него не добавляя при создании.
3. Добавьте этот репозиторий в качестве удаленного для вашего локального
   репозитория (`git remote add`).
4. Отправьте данные из локального репозитория в удаленный (`git push`).
5. Убедитесь, что на web-странице Github отображаются файлы вашего репозитория.

### Синхронизация с удаленным репозиторием

1. Создайте папку вне вашего репозитория.
2. Получите копию вашего репозитория в этой папке с помощью `git clone`.
3. Убедитесь, что файлы совпадают с файлами в вашем репозитории.
4. Добавьте в этом репозитории последние протоколы в ваш отчет и закоммитьте их.
5. Отправьте эти изменения в удаленный репозиторий.
6. Вернитесь в ваш первый локальный репозиторий.
7. Запросите обновления из удаленного репозитория с помощью `git fetch`.
   Объясните вывод команды.
8. Синхронизируйте содержимое репозитория для основной ветки с `git pull`.

### История изменений

Получите сводку последних изменений с помощью `git log`. Приведите ее в отчете.

## Задания со звездочкой

Эти задания необязательны для зачета или автомата, но полезны тем, кто хочет
глубже разобраться с гитом.

1. Настройте ваше имя и почту по-разному для двух копий разного репозитория.
2. Внесите в файл два изменения в разных частях, но закоммитьте только один.
3. Откатите закоммиченные изменения на коммит назад а) убрав изменения
   полностью, б) оставив изменения не проиндексированными.
4. Переключитесь на отдельный коммит и создайте из него ветку.
5. Выполните аналогичные задания из раздела "Слияние веток", но делая `rebase`
   вместо `merge`. Объясните разницу.
6. Добавьте удаленный репозиторий не на другом компьютере, а в другой директории
   на этом же.
