# Лабораторная работа №3. Настройка среды разработки

## Цель работы

Познакомить студента с базовыми приемами настройки своих инструментов
разработки, с помощью которых он сможет удобнее настроить свои рабочие процессы
под себя.

## Процесс работы

По ходу выполнения работы фиксируйте промежуточные шаги для каждого этапа. Для
консольных команд в конце каждого этапа копируйте в отчет команды, которые
привели к успеху и их вывод, добавляя небольшое описание.

Для заданий, отмеченных ключевым словом *Узнайте*, выпишите в отчет краткий
конспект информации и укажите используемые источники.

Если какая-то функция не представлена напрямую в вашей программе, попробуйте
каким-то удобным образом совместить несколько программ. Главное, чтобы получился
удобный вам процесс.

## Этапы выполнения работы

### Для начала

1. Зафиксируйте, какими программами вы пользуетесь для следующих действий:

  - редактирование текстовых файлов, которые попадаются вам на пути;
  - программирования на главном для вас языке программирования;
  - для выполнения команд в консоли;
  - для навигации по файловой системе и манипуляций с файлами;
  - для работы с гитом.

2. *Узнайте*, какие есть альтернативы для каждой из программ для вашей цели.
   Может быть, какая-то из других программ вам понравится больше? В таком случае
   попробуйте попользоваться ей в течении нескольких дней (лучше - недели) и
   кратко опишите разницу.

### Look and Feel

1. *Узнайте*, каким образом в ваших программах настраиваются цвета интерфейса
   и шрифты.
2. Постарайтесь найти удобное сочетание для каждой программы. Отразите в отчете
   изменения.
3. *Узнайте*, каким образом можно настроить в этих программах расположение
   элементов интерфейса (левые и правые, верхние и нижние панели).
4. Попробуйте настроить расположение - может быть вам понравится иначе, чем у
   вас было? Отразите в отчете, что вы попробовали и изменения, если они были.
5. *Узнайте*, каким образом можно настроить в командной строке приглашение ко
   вводу. Поищите примеры того, какую информацию можно выводить в приглашении
   ко вводу (текущее время, ветку гита, сокращенный путь к директории).
6. Настройте эту часть так, чтобы вам нравилось. Зафиксируйте в отчете те
   параметры конфигурации, которые вы использовали.

### Эргономика работы с кодом

1. Изучите список горячих клавиш для редактирования текста в вашем редакторе,
   выпишите несколько наиболее интересных (например, вставить строку ниже и
   перейти на нее).
2. *Узнайте*, каким образом в вашем редакторе можно сделать следующие действия:

  - поиск по содержанию файлов,
  - перейти к объявлению функции или типа;
  - перейти к реализации функции или типа;
  - найти все места, где используется переменная, функция или тип;
  - переименовать все вхождения переменной, функции или типа;
  - быстро перемещаться между несколькими наиболее интересными местами кода;
  - комментировать и раскомментировать большие части кода.

### Кастомизация процессов

1. *Узнайте*, каким образом можно создавать свои горячие клавиши и какие
   действия можно к ним привязывать.
2. Настройте, чтобы можно было по кнопке из интерфейса и/или по сочетанию клавиш:

  - собирать программу в нужной среде (например, в WSL),
  - запускать программу в режиме отладки или релиза,
  - запускать автоматические тесты проекта.

### Интеграция с гитом

1. Настройте интеграцию с гитом в вашей среде разработки, чтобы работу с системой 
   контроля версий можно было проводить из интерфейса.
2. *Узнайте*, каким образом можно делать в вашей среде разработки:

  - просмотр изменений,
  - добавление файлов в индекс,
  - коммиты,
  - добавление удаленного репозитория,
  - получение обновлений из удаленного репозитория,
  - отправка обновлений в удаленный репозиторий,
  - разрешение конфликтов.
