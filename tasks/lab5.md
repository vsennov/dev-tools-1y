# Лабораторная работа №5. Средства управления проектами.

## Цель работы

Познакомить студента с простыми техническими средствами управления проектами на
основе задач (tickets/issues).

## Процесс работы

По ходу выполнения работы фиксируйте промежуточные шаги для каждого этапа.

Для заданий, отмеченных ключевым словом *Узнайте*, выпишите в отчет краткий
конспект информации и укажите используемые источники.

## Этапы выполнения работы

### Создание и настройка проекта

1. Создайте в вашем репозитории Github проект, посвященный разработки курсовой
   работе. Убедитесь, что преподаватель имеет доступ к проекту.
2. Настройте необходимые этапы для задач по вашему проекту, чтобы реализовать
   следующий рабочий процесс. Существуют задачи, которые могут быть (частично)
   сформулированы, но делать их пока что не надо. В некоторый момент решается,
   что эта задача должна быть выполнена в ближайшее время, но при этом
   исполнитель еще не работает над ней. Когда исполнитель берется за эту задачу,
   он отмечает это в задаче; когда работа над задачей закончена, она переводится
   на согласование/защиту. По итогам согласования или защиты задача может либо
   закрыться, либо вернуться на доработку.
3. Добавьте поля в ваши задачи, в которых можно было бы отмечать предполагаемые
   даты начала и окончания.
4. Добавьте поле в ваши задачи, которые бы отражали тип работы:
   исследовательская работа, составление документации, программирование.

### Планирование работ по курсовой работе

1. Декомпозируйте работу над курсовым проектом по "Структурам данных" на
   небольшие задачи, каждую из которых можно было бы сделать за 4-10 часов.
   Задачи могут быть примерно следующими: изучения формулировки задания и
   составление более подробной постановки задачи, изучение существующих подходов
   к решению, развертывание проекта для проведения первичных экспериментов,
   составление алгоритма, реализация и прочее. Каждая задача должна иметь
   короткое описание, в котором было бы сформулировано, что требуется и какие
   артефакты (тексты) должны получиться по итогу выполнения.
2. Создайте тикеты в терминах проекта Github для декомпозированных выше задач,
   задайте им нужные типы и проставьте примерные сроки.
3. Задайте связи между задачами, которые зависят друг от друга, то есть
   результаты одной задачи необходимы для другой.

### Выполнение задачи

1. Создайте для задачи, которая а) имеет результатом текст (например,
   постановку, алгоритм или код), б) требует согласования, черновой запрос
   на слияние, привязанный к этой задаче.
2. Добавьте в преподавателя в этот запрос в качестве ревьювера.
3. Двигайте тикет задачи по доске соответственно состоянию вашей задачи в
   процессе.
4. Когда задача будет на согласовании, переведите черновой запрос на слияние
   в готовый.
5. По итогам ревью переводите задачу в нужную стадию на доске, пока запрос на
   слияние не будет принят.

### Исследование альтернатив

1. *Узнайте*, какие еще решения для управления проекта можно использовать для
   реализации похожего процесса. *Узнайте*, какие возможности и ограничения, в
   частности в разрезе тарифных планов, имеют эти решения.
2. Выберите одну альтернативу и опишите, как можно было бы выполнить те же
   задания, используя ее.
