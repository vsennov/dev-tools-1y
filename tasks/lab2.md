# Лабораторная работа №2. Git Flow, Code Review

## Цель работы

Познакомить студента с (распространенным) вариантом организации совместной
работы над новой функциональностью и проведения инспекции кода.

## Процесс работы

По ходу выполнения работы фиксируйте промежуточные шаги для каждого этапа. Для
консольных команд в конце каждого этапа копируйте в отчет команды, которые
привели к успеху и их вывод, добавляя небольшое описание.

Для заданий, отмеченных ключевым словом *Узнайте*, выпишите в отчет краткий
конспект информации и укажите используемые источники.

## Этапы выполнения работы

### Подготовка репозитория

1. Создайте в вашем репозитории папку `labs`, создайте в ней папку `lab1` (или
   `lab2`, `lab3` и т.д.). Добавьте туда код для еще не выполненной работы по
   программированию (например, по дисциплине "Структуры данных").
2. *Узнайте*, зачем нужен и как работает файл `.gitignore` в git.
3. Добавьте файл `.gitignore` в папку с работами по программированию, настройте
   этот файл так, чтобы в индекс не попадали файлы сборки (обычно папка `build`
   или `out`).
4. Закоммитьте изменения и сделайте пуш в удаленный репозиторий, в основную
   ветку.

### Защита веток

1. *Узнайте*, как работает защита веток в Github.
2. Защитите вашу основную ветку, запретите в пуш в эту ветку.
3. Проверьте, что никакие изменения нельзя больше запушить из локального
   репозитория. (Чтобы удалить проверочный коммит, используйте `git reset`).
4. В локальном репозитории создайте новую ветку `pr-test` из основной и
   проверьте, что вы можете ее запушить в удаленный репозиторий.

### Запросы на слияние

1. Добавьте изменения в ветку `pr-test` и отправьте их в удаленный репозиторий.
2. Через web-интерфейс GitHub создайте запрос на слияние (Pull Request, PR)
   ветки `pr-test` с основной.
3. Примите PR и проведите слияние.
4. В локальном репозитории примените последние обновления основной ветки (`git
   pull`).

### Code Review

1. В локальном репозитории создайте новую ветку `prog-lab1` из последней версии
   основной ветки.
2. Выполняйте работу по программированию, создавая коммиты после рабочий
   сессий. Отправляйте эти коммиты в удаленный репозиторий. (Этот пункт может
   затянуться...)
3. Когда работа готова к защите, создайте PR в основную ветку, укажите
   преподавателя в качестве ревьювера.
4. Получайте правки в виде комментариев к коду и исправляйте их коммитами. 
5. Когда преподаватель поставит отметку `Approve`, слейте ветку и приступайте к
   следующим работам.
