# Лабораторная работа №7. Развертывание на целевой машине.

## Цель работы

Познакомить студента с простым сценарием подготовки целевой машины и доставки
программного продукта на нее.

## Процесс работы

Эта работа выполняется в группах по два или три человека. В группе каждый
студент подготавливает виртуальную машину для другого студента в группе, он же
должен развернуть на этой машине свою программу.

Например, Армен и Боря объединились в группу; тогда Армен готовит виртуальную
машину, чтобы Боря развернул там свой код, а Боря готовит виртуальную машину
для Армена. Если же Алиса, Белла и Варя объединились в группу, то Алиса готовит
машину для Беллы, Белла готовит для Вари, а Варя — для Алисы.

Каждый из студентов отмечает в отчете шаги для подготовки, которую он делал, и
те шаги, которые он делал для развертывания.

По итогу выполнения группа показывает в аудитории их виртуальные машины и
повторяет в реальном времени шаги для раскатки.

## Этапы выполнения работы

### Создание виртуальной машины

1. Определите, какой дистрибутив вам нужно использовать, согласно инструкциям в
   [работе №4](./lab4.md).
2. Выберите платформу виртуализации для создания машины Linux. Это можно сделать
   в программе виртуализации типа VirtualBox (см. указания в работе 4), можно
   сделать в WSL (Docker использовать нельзя).
3. *Узнайте*, какие потенциальные опасности имеет наличие доступа внешнего
   человека к вашей виртуальной машине: к каким файлам, к каким ресурсам системы
   будет иметь доступ другой человек. Возможно, вы сделаете другой выбор в п. 2.
4. Создайте виртуальную машину с нужной системой **без графической среды**, для
   этой работы будет достаточно консольного доступа.

### Настройка удаленного доступа

1. Установите (или найдите) у себя на машине клиент для подключения по протоколу
   SSH.
2. Настройте в вашей виртуальной машине службу
   [OpenSSH](https://www.openssh.org/), прочитайте в Wiki вашего дистрибутива,
   как это сделать.
3. *Узнайте*, что такое порт TCP, *узнайте*, что такое пробрасывание портов.
4. Настройте пробрасывание портов так, чтобы можно было подключиться из вашей
   основной операционной системы в виртуальную машину. Подключение осуществите
   по паролю.
5. *Узнайте*, как добавить публичный ключ для подключения на сервер без пароля.
6. Добавьте ваш публичный ключ на виртуальную машину, проверьте, что вы можете
   подключиться к вашей виртуальной машине без пароля.
7. Отключите доступ по паролю в настройках службы SSH-сервера. Проверьте, что
   подключение по паролю больше не доступно.

### Настройка сессии для другого пользователя

1. Добавьте пользователя для вашего напарника в систему на виртуальной машине.
   Для пользователя необходимо также создать домашнюю директорию.
2. Попросите вашего напарника передать его публичный ключ для подключения по
   ssh.
3. Поместите ваши компьютеры в одну локальную сеть (например, с общей точки
   доступа WiFi).
4. Узнайте IP-адрес вашего компьютера в этой сети. Проверьте, что с компьютера
   напарника есть доступ до вашего компьютера (ping).
5. *Узнайте*, как открыть и закрыть порт для доступа из локальной сети.
6. Попробуйте **на время** открыть порт, чтобы ваш товарищ смог подключиться
   по ssh. После окончания упражнений верните прежние сетевые настройки,
   наличие открытых портов опасно в сетях, где могут быть злоумышленники или
   их программы!

### Развертывание программы

Эту часть работы вы выполняете с помощью удаленного подключения к компьютеру
вашего напарника. Вам нужно будет сделать (а потом продемонстрировать на
занятии) следующее: клонировать ваш приватный репозиторий с лабораторными по
"Структурам данных", выполнить сборку и запустить тесты.

1. Сформулируйте, какие программы нужны на удаленной машине для выполнения этих
   действий (гит, компилятор, система сборки...). Сформулируйте список этих
   программ; убедитесь, что они установлены на целевой машине (установите сами
   или попросите вашего напарника).
2. Подключитесь к удаленной машине, склонируйте ваш приватный репозиторий.
   Подумайте, как организовать доступ, стоит ли добавлять ваш приватный ключ на
   эту машину, чем это может грозить?
3. Запустите сборку вашего проекта, продемонстрируйте, что программа собирается,
   тесты проходятся и главная программа может быть запущена в консоли.
